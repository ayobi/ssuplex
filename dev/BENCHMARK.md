# Benchmarks

This document describes how SSUplex is compared with Metaxa2: the software
environment, the datasets, the commands, and how each number is computed.
Every input is either downloaded from a public archive or generated by a
script in this directory.

## Software environment

Run both tools against the same HMMER build so that differences reflect the
implementations rather than HMMER versions. Metaxa2's Bioconda package
(`metaxa`) requires HMMER 3.1, which cannot be installed alongside HMMER 3.4,
so Metaxa2 is run from its official download, which uses whatever HMMER and
legacy BLAST are on `PATH` (its scripts also need a system Perl):

```bash
conda create -n ssuplex-bench -c conda-forge -c bioconda \
    hmmer=3.4 blast-legacy=2.2.26 mafft perl psutil matplotlib
conda activate ssuplex-bench
curl -L -O https://microbiology.se/sw/Metaxa2_2.2.3.tar.gz
tar xzf Metaxa2_2.2.3.tar.gz
export PATH="$PWD/Metaxa2_2.2.3:$PATH"
cargo build --release --locked
```

Each harness writes a `versions.txt` recording the SSUplex version, the paths
and versions of `nhmmer` and of the `hmmsearch` Metaxa2 uses, the Metaxa2
version, and the machine.

Profiles are assembled from the same download as described in the README
(`dev/assemble_metaxa2_hmms.sh Metaxa2_2.2.3/metaxa2_db hmms`).

## Datasets

| Dataset | Source | Truth |
| ------- | ------ | ----- |
| Metaxa2 test file | `Metaxa2_2.2.3/test.fasta` | 100 sequences: records 1 to 50 are LSU (negatives for SSU), records 51 to 100 are SSU, ten per origin; the origin is the last character of each ID (A, B, C, E, M) |
| ZymoBIOMICS mock, ONT 16S | SRA run SRR10391201 (BioProject PRJNA587452) | every read is bacterial |
| Rice root, ONT 16S | SRA run SRR25243163 (BioProject PRJNA992961) | none per read; compared with Metaxa2 only |
| Metaxa2 reference set | sampled from the Metaxa2 SSU database with `make_truth_set.py` | origin code in each reference ID |

The reference set comes from the same database as the profiles, so it measures
performance on sequences the profiles were built from, not on new sequences.

Public reads are subsets of the first N reads of a run, fetched with:

```bash
dev/fetch_ena_reads.sh SRR10391201 200000 zymo_200k.fasta
dev/fetch_ena_reads.sh SRR25243163 5000 rice_5k.fasta
```

Truth tables have a header line and two columns, `read_id` and `true_origin`
(`bacteria`, `archaea`, `eukaryota`, `mitochondria`, `chloroplast` or
`(negative)`). For the two labelled real datasets:

```bash
# Metaxa2 test file
awk 'BEGIN{print "read_id\ttrue_origin"; m["A"]="archaea"; m["B"]="bacteria";
           m["C"]="chloroplast"; m["E"]="eukaryota"; m["M"]="mitochondria"}
     /^>/{k++; id=substr($1,2); print id "\t" ((k<=50) ? "(negative)" : m[substr(id,length(id))])}' \
  Metaxa2_2.2.3/test.fasta > testfasta.truth.tsv

# ZymoBIOMICS subset (all bacterial)
awk 'BEGIN{print "read_id\ttrue_origin"} /^>/{print substr($1,2) "\tbacteria"}' \
  zymo_5k.fasta > zymo_5k.truth.tsv
```

The reference set (needs `fastacmd` from `blast-legacy`):

```bash
python3 dev/make_truth_set.py --db Metaxa2_2.2.3/metaxa2_db --out ref \
    --per-origin 100 --negatives 10 --seed 42
```

## Accuracy and agreement

All four datasets in one command (fetches the reads, builds the truth tables
and the reference set, and runs each dataset as below; reports are collected
in `ALL_REPORTS.txt`):

```bash
dev/run_real_data.sh --metaxa2-dir Metaxa2_2.2.3 --out accuracy --threads 16
```

A single dataset:

```bash
dev/run_benchmark.sh --db Metaxa2_2.2.3/metaxa2_db --reads zymo_5k.fasta \
    --truth zymo_5k.truth.tsv --out bench/zymo_5k --threads 8
```

This runs Metaxa2's default pipeline once, which gives two sets of calls: its
HMM-stage origin (the `Origin` column of `run.extraction.results`, the step
SSUplex reimplements) and its final origin (the per-origin FASTA files, which
also use BLAST matches). It then runs SSUplex with `--rank mean`, `sum` and
`count`, and scores all five call sets with `dev/score_origins.py`, writing
`report.txt`, `calls.tsv` (one row per read) and `rank_disagreements.tsv`.

Definitions used for every method:

- **Accuracy**: correct calls divided by all reads whose true origin is one of
  the five SSU origins. Reads a tool leaves undetected, unclassified or
  uncertain count as errors.
- **Negatives rejected**: reads labelled `(negative)` for which no SSU origin
  was called.
- **Per-class recall** and a **confusion matrix** (rows: truth; columns: call,
  including `uncertain` and `unclassified`) for each method.
- **Agreement with Metaxa2**: among reads both tools assign to an SSU origin,
  the fraction with the same origin; reported against both Metaxa2 stages. On
  data without per-read truth this is agreement, not accuracy.
- **Ranking disagreements**: reads where mean, sum and count give different
  origins, with the per-origin region counts and mean and summed scores from
  `--debug-scores`.

### Results

Produced with `dev/run_real_data.sh` (first 5,000 reads of each public run;
reference set with `--per-origin 100 --negatives 10 --seed 42`) on an AMD Ryzen 9
9950X with HMMER 3.4 and Metaxa2 2.2.3. Accuracy against known origins:

| Dataset | SSU reads | Metaxa2 HMM stage | Metaxa2 final | SSUplex sum | SSUplex mean | SSUplex count |
| ------- | --------: | ----------------: | ------------: | ----------: | -----------: | ------------: |
| Metaxa2 test file | 50 | 96.0% | 100% | 96.0% | 96.0% | 66.0% |
| Metaxa2 reference set | 500 | 94.8% | 99.8% | 95.6% | 96.8% | 79.2% |
| ZymoBIOMICS ONT | 5,000 | 54.9% | 99.96% | 95.9% | 43.0% | 95.7% |

Every method rejected all 50 LSU sequences in the test file and all 10 random
negatives in the reference set.

The rice-root sample has no per-read truth. Reads assigned to each origin, and
agreement with Metaxa2's final (BLAST-assisted) calls among reads both assign to
an SSU origin:

| Method | Bacteria | Mitochondria | Chloroplast | Organellar | Agreement with Metaxa2 final |
| ------ | -------: | -----------: | ----------: | ---------: | ---------------------------: |
| Metaxa2 HMM stage | 1,237 | 1,741 | 1,987 | 74.6% | 66.9% |
| Metaxa2 final | 2,873 | 352 | 1,769 | 42.4% | |
| SSUplex sum | 3,008 | 231 | 1,761 | 39.8% | 96.8% |
| SSUplex mean | 1,141 | 1,602 | 2,248 | 77.0% | 64.5% |
| SSUplex count | 3,765 | 137 | 1,098 | 24.7% | 81.6% |

### Choice of the default ranking statistic

The mean, which is also the default of Metaxa2's HMM-based step, assigns many
noisy bacterial reads to chloroplast or mitochondria: on the ZymoBIOMICS reads
SSUplex with mean scored 43.0% and Metaxa2's HMM stage 54.9%. On the reads
where the statistics disagree, the bacterial profiles matched a median of 9
regions against 4 for the organellar origins, at a slightly lower mean score. The sum is the only
statistic that is above 95% on every labelled dataset and it agrees with
Metaxa2's final calls on 96.8% of the rice reads, so it is the default. Its
errors run the other way: chloroplast reference sequences (80 of 100 correct)
and reads Metaxa2 calls mitochondrial in the rice sample (134 of 352 assigned to
bacteria) can go to bacteria, which has more profiles (15, against 12 for
chloroplast and 10 for Metaxa2's M set).

Normalising the sum by the number of profiles in each origin's set, as
Metaxa2's own `sum` option does, was also evaluated, offline from the same hits
with `dev/compare_rank_rules.py`. With M and N scored separately it is accurate
on clean sequences (100% on the test file, 96.2% on the reference set) but sends
noisy bacterial reads to mitochondria (80.6% on ZymoBIOMICS; 1,280 rice reads
called mitochondrial). With M and N together it loses most mitochondria (2 of
10 in the test file; 45 rice reads). Neither was adopted.

The default was chosen on these four datasets.

```bash
python3 dev/compare_rank_rules.py --hmm-src Metaxa2_2.2.3/metaxa2_db/SSU/HMMs \
    accuracy/testfasta accuracy/ref accuracy/zymo accuracy/rice
```

## Independent simulated benchmark

The labelled real datasets above either come from the Metaxa2 database or
contain bacteria only. The simulated benchmark adds labelled reads for all five
origins from sequences outside the Metaxa2 database, at three read accuracies.

```bash
conda create -y -n ssuplex-sim -c conda-forge -c bioconda python=3.12 badread vsearch
dev/sim/run_simulation.sh --metaxa2-dir Metaxa2_2.2.3 --out sim --threads 16
```

- **Sources** (`dev/sim/build_sources.py`). Bacteria, archaea and nuclear
  eukaryota come from SILVA 138.2 SSU Ref NR99, without entries SILVA labels as
  chloroplast or mitochondria. Mitochondria and chloroplasts come from the SSU
  rRNA genes annotated in the NCBI RefSeq mitochondrion and plastid genome
  releases (chloroplasts only; partial and split genes are skipped). Sequences
  whose accession is in the Metaxa2 database are excluded and identical sequences
  are collapsed. For each candidate, `vsearch` finds the closest Metaxa2
  database sequence, and sources are drawn evenly from three novelty bands per
  origin: 99% identity or more, 97 to 99%, and below 97% (a band's shortfall is
  filled from the others). Negatives are SILVA 138.2 LSU sequences and
  composition-preserving shuffles of SSU sources. The defaults are 2,000 sources
  per origin and 2,000 negatives.
- **Reads** (`dev/sim/simulate_reads.py`). Every source yields full-length reads
  (two per profile by default) from a random strand, with errors added by
  Badread's empirical error models used as a library: `ont_r9` (nanopore2020
  model, mean identity 92%), `ont_r10` (nanopore2023, 98.5%) and `hifi_like`
  (pacbio2021, about Q30, 99.9%).
- **Scoring**. Each profile runs through `dev/run_benchmark.sh`, so Metaxa2's
  two stages and SSUplex's three statistics are scored with the definitions
  above. `dev/sim/score_by_band.py` then reports recall by origin and novelty
  band, recall for metazoan and non-metazoan mitochondria, negatives rejected,
  and the accuracy and organellar share each method would report for a
  bacteria-dominated sample and a plant-root-like sample (computed from the
  per-origin call rates, which do not depend on composition).

The download record (`sim/db/download_record.txt`) notes the RefSeq release
used. All randomness is seeded.

## Run time and memory

```bash
dev/run_timing.sh --reads zymo_1M.fasta --hmm-dir hmms --out timing \
    --sizes "5000 25000 100000 200000 500000 1000000" --reps 3 --threads 12
```

For each size the harness takes the first N reads, then runs SSUplex (default
settings) and Metaxa2 with `-x T` (extraction only, the step SSUplex
reimplements) in alternation, `--reps` times each. `dev/peakmem.py` records for
every run:

- wall-clock time;
- **peak memory of the whole process tree**, sampled every 0.05 s, so that
  helper processes (`nhmmer`, `hmmsearch`) running at the same time are added
  together;
- the largest single process, as reported by `/usr/bin/time`, for comparison;
- total CPU time.

`dev/plot_timing.py` writes a summary table (median, minimum and maximum over
replicates), the speed-up and memory ratio at each size, and the figure, which
shows measured points only, on log-log axes. Add `--m2-mode full` to time
Metaxa2's default pipeline, including BLAST classification, as a separate
reference; `plot_timing.py <timing.tsv> <prefix> --full <timing_full.tsv>` adds
it to the figure.

Metaxa2 keeps batches of sequences in memory and sizes them according to the
memory available, so its peak memory depends partly on the machine; report the
machine with the results.

## Smoke test

`dev/smoke.sh` builds synthetic profiles and reads, runs SSUplex, and checks
routing, read accounting, clipping coordinates and overwrite protection. It
needs `hmmbuild` and `nhmmer` and runs in CI.
